# Tests 🧪✔️
This folder contains some useful scripts for testing some specific functionalities. To have a clearer understanding of all the parameters imported from the codes in [utils](https://github.com/ChristianCella/workcell_optimization/tree/txt_arto/utils), look at [this](https://github.com/ChristianCella/workcell_optimization/blob/txt_arto/utils/readme.md) readme file.

- ```drag_robot.py``` implements $\texttt{RViz}$-like functionalities, allowing to use a GUI with sliders to move each joint of the robot (```CONTROL_MODE = "joints"```) or a specified frame in Cartesian terms (variables ```CONTROL_MODE = "cartesian"``` and ```BODY_NAME = "tool_tip_proxy"```).
- ```forward_kinematics.py``` allows to specify a set of joints $\mathbf{q}$ and retrieve the Cartesian pose of a certain site.
- ```inverse_dynamics.py``` allows to verify if the torques are computed correctly for a specified joints configuration. The total torques are the sum of those needed to counteract gravity ($\boldsymbol{\tau_g}$) and those needed to generate on the enviroment the prescribed wrench ($\boldsymbol{\tau_e} = \mathbf{J}^{\top}\mathbf{w}$). Important: $\texttt{MuJoCo}$ always returns the Jacobian expressed in terms of world coordinates. For this reason, for $\boldsymbol{\tau_e}$ to be computed correctly, the wrench must be expressed in terms of world coordinates (it depends on the meaning of the values inserted in the database). Since the center of mass (COM) of the body may be shifted from the site location, for the simulation to be coherent, a correction factor must be applied. However, the computations of $\boldsymbol{\tau_e}$ do not change: the only aspect to be accounted for is the moment `T_com` that must be added to apply the correct wrench on the body.
- ```inverse_kinematics.py``` uses the capabilities of $\texttt{ikflow}$ defined in [ikflow_inference.py](https://github.com/ChristianCella/workcell_optimization/blob/txt_arto/utils/ikflow_inference.py). It relies on some parameters defined in the class $\texttt{TestIkFlow}$ contained in [constant_parameters.py](https://github.com/ChristianCella/workcell_optimization/blob/txt_arto/utils/constant_parameters.py), and it allows to retrieve a set of possible joint configurations for a given Cartesian pose, that can either be taken from the database (```use_database=True```) or leverage the hard-coded pose inside the class.
